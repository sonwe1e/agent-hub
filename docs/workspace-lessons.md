# 多 Agent 工作台：设计记录与经验

本次目标是在现有 Agent Hub 上支持全局技能与指令分发、原生会话继续与跨端交接、额度提醒及日常快捷入口。协作采用协调、专项调研、分模块实现、隔离测试和交叉审查；不同 Agent 的模块交给独立审查者核查，发现问题后由实现者修复并补充回归。

## 已确认的产品选择

- 五个客户端共用按项指定的主来源；首次发布必须预览确认，后续自动同步按项开启。
- 全局指令的各端差异由明确配置的文本替换表达；不会自动猜测或改写客户端身份。项目规则和 MCP 不在能力库范围。
- 原端恢复与跨端交接都要支持；交接草稿先预览、允许编辑，是否立即开始由用户选择，默认关闭。
- 额度不足提前提醒，已观测的实际受限也提示；不自动切换线路、账号或模型。
- 主窗口承担详细操作，托盘提供少量快捷入口。

## 对实现有实际影响的发现

1. 多个客户端可能共同读取用户目录下的 .agents/skills，OpenCode 也可能发现 Claude 的技能目录。因此“尚未发布”只能描述 Hub 是否分发，不能保证共享目录中的主来源没有被客户端直接发现；发布预览必须显示这一差异。
2. 指令中的客户端身份不应被当作跨端通用文字。显式配置端侧替换并在预览中展示，自动同步遇到有依据的失配时应暂停相应目标，不能用静默猜测补齐。
3. 文件预览通过并不代表随后写入时目标仍未变化。审查用隔离进程复现了检查后外部写入、Windows 已打开写句柄、不同 Hub 数据根并发、写入中途退出等情况；修复后以实际旧文件保护、共享目标锁、原子预留标记和事务阶段记录进行复验。强制终止测试不代表断电持久性，相关实现与限制见[能力库说明](capability-library.md)。
4. 恢复旧发布后不能立即由自动同步重新推回新版本；恢复自动同步项时改回手动，用户可以随后重新开启。
5. 原生会话标识、项目目录和安装实例需要分别验证。启动进程只证明已尝试启动，不能证明客户端恢复完成；跨端的工具状态和隐藏上下文不保证可迁移。
6. 交接摘要属于一次独立模型调用：先展示完整材料、模型和接收方，再明确发送。预览与派发时核验线路和订阅身份，但其他程序同时切换账号时仍存在网关读取凭据之前的并发窗口。[摘要边界](handoff-summary.md)
7. 本机索引中的订阅线路错误不记录请求时的账号身份。额度快照与当前账号绑定；已索引的 429 只表述为线路可能受额度或速率限制，账号归属未知。
8. 交互验收要覆盖自动刷新和未保存草稿，不能只检查页面首次渲染。无模型的临时客户端、合成原生日志、本机模拟上游与真实账号验证分别记录，不能互相代替。
9. 技能目标与发布快照的文件内容一致，不等于正在运行的客户端已经重新加载。批量覆盖前需要逐端展示差异、保留独立恢复点，并按实际事务分别报告成功或失败。
10. 取消已有线路时，单纯把它标为不可用可能使原有解析逻辑落到其他默认线路。原有选择需要显式阻断并提示重新选择，才能遵守不自动切换的产品决定。
11. 会话索引默认不保存标题时，可从已验证的原生日志按需读取客户端标题或用户消息节选。列表要标明来源；保留水位与脱敏仍需生效，节选本身也可能包含个人内容。
12. 实际网关记录可能只有会话 ID 与用量，没有原生文件或正文，不能按时间猜测归属。用户选择保存简短脱敏标题后，可对新网关请求记录标题；清理水位必须同时约束在途请求，历史缺失的标题仍需手动补充。
13. 目录整理必须同时检查源码入口、模块身份和打包后的子进程：旧模块导入需要与新实现共享同一个模块对象，否则全局状态和测试替换会分叉；编译预览还须跟踪实际参与计算的源码。静态资源移动后，也要保留脚本加载顺序并验证两种界面传输。
14. 测试发现、共享夹具和截图输出各自依赖既有目录约定。把业务实现分区并提供功能到测试的导航，可以先提升定位效率；浏览器回归和桌面打包应使用隔离副本及合成配置，避免覆盖已有截图、程序或用户数据。

自动测试与真实验证的具体范围记录在各模块说明和测试文件中。本记录描述协作中的观察与修正，不证明用户满意度或长期使用效果。
