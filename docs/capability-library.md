# 全局技能与指令能力库

能力库维护用户明确导入的主来源，不会自动接管发现到的文件。当前仅覆盖全局技能目录与全局指令，不管理项目规则、MCP 或子代理。`discover()` 只读取目录和文件是否存在等元数据，返回候选位置；用户仍需明确选择主来源、名称及目标。默认手动发布，自动同步须逐项开启。

## 位置与发现范围

下面是默认用户目录下的本期写入目标。客户端的自定义 home、profile、插件、远程会话和项目级覆盖可能改变其实际加载位置；写入成功并不证明正在运行的会话已加载或模型遵循内容。写入能力已通过临时目录模拟验证，五个真实客户端的完整端到端加载仍需单独验收。

| 客户端 | 技能目标 | 全局指令目标 | 资料及已验证边界 |
| --- | --- | --- | --- |
| Claude Code | `.claude/skills/<name>` | `.claude/CLAUDE.md` | [官方技能](https://code.claude.com/docs/en/skills)、[全局指令](https://code.claude.com/docs/en/memory)。`synced` 与 `anthropic-skills` 为保留名称。 |
| Codex | `.codex/skills/<name>` | `.codex/AGENTS.md` | [官方技能](https://developers.openai.com/codex/skills)强调共享 `.agents/skills`；本机 Codex CLI 0.165.0 在隔离 home 的 `skills/list` 同时发现 `.codex/skills` 与 `.agents/skills`。 |

## 版本、冲突与恢复

- 一项有一个绝对路径主来源，技能按完整目录复制，包含参考资料和脚本；不支持符号链接、junction 或其他重解析点。指令源须为 UTF-8 文件。源与目标相同会跳过写入；技能来源与目标互相包含时拒绝操作。
- 手动发布时保存内容快照；尚未发布的更改不会同步到其他目标。新目标可以使用最近发布的快照，避免意外传播工作中修改。
- 指令可为目标分别设置用户明示的精确文本替换，按列表顺序替换所有匹配；默认没有替换。示例：`{"pi":[{"from":"--agent codex","to":"--agent pi"}]}`。不同端执行前可在预览中看到最终区块的差异；未匹配的替换、残留的其他客户端身份标识都会提示，但 Hub 不猜测并修改身份。目标即主来源时不改写主来源，该目标的替换不会生效。
- 每次发布快照同时保存指令正文与当时的按端替换；替换变化也计入来源哈希。分发已发布版本使用该版本保存的替换，不会提前应用尚未发布的新映射。自动同步必须先显式预览并发布第一版。
- 指令写入各自的受管理注释区块，保留区块外内容。一个全局文件作为主来源时会排除其中由 Hub 写入的区块，避免递归传播。
- 技能目标已有非本库管理的目录，或已管理的技能／指令区块被改动，视为冲突；默认停止。预览可以明确选择覆盖特定目标，再应用该预览；应用前再次核对文件。覆盖会保留变更前快照，只有明确选择冲突目标才生效。
- 已管理技能可在列表全选后批量预览各端，冲突目标也可一键全选，再重新预览并确认。批量操作按技能逐项执行、分别记录结果与恢复点；某项失败不会回滚其他已完成项。待恢复事务不可强制覆盖，取消或重新预览会释放不再使用的预览。目标显示“与发布版一致”仅代表文件与 Hub 的发布快照一致，并不证明运行中的客户端已经重新加载。
- 仅对已开启自动的条目执行同步；一个目标冲突时可保留该目标并同步其他目标。已配置的端侧替换找不到原文，或发现其他客户端身份的硬编码时，自动同步暂停受影响的端并提示，其余端仍可同步；手动发布时由用户查看差异和警告后决定。后台调度者要求相同主来源哈希连续稳定后再调用，以降低多文件编辑中间状态被发布的可能。稳定观察并不证明外部程序不会继续修改。
- 发布记录与内容快照保存在 Hub 本机数据目录 `capability-library/`，可查看并按逆序恢复最近事务。写入先将目标移动到本客户端配置目录下的 `.agent-hub-transactions/`，再核验实际移走的内容，使用不覆盖既有目标的重命名放入新版本。每个目标还设有跨 Hub 数据根共享的锁及待恢复标记，标记先写临时文件并完成后原子提交；只有全部目标预留完成并记入事务，才开始交换。预留阶段中断时恢复只清除属于本次事务的标记，保留其他 Hub 可能已做的修改；交换阶段异常中断后，即使其他 Hub 配置想更新同一目标，也必须先在原数据根恢复该事务。其他程序在交换时创建或修改目标时，写入会停止并保留已有内容。中断状态显示在发布记录中，可尝试恢复；若目标或备份发生后续变更，恢复会停止并保留冲突内容。指令恢复仅处理当前项目的受管理区块，保留其他项目的区块和区块外改动。
- 恢复成功会将该项自动同步暂停并改为手动，防止当前主来源重新覆盖恢复版本；需要自动同步时可再开启。停止管理只移除 Hub 跟踪，保留主来源和目标文件；以前的指令区块也会保留。重新导入同名指令时会提示旧区块冲突，只有在预览中明确选择接管才替换该旧区块；可恢复为接管前的内容。

事务文件、快照及 `.agent-hub-transactions/` 中保留的实际旧目录、临时版本可能包含完整技能、脚本和指令正文；后者位于各客户端配置目录中，不在 Hub 数据目录中。为了保留外部进程在移动之后仍通过旧句柄写入的内容，这些文件目前不会自动删除，会持续占用磁盘。它们不上传，也不会放在会被递归发现为技能的目录里。单个来源限制为 32 MiB 和 2000 个文件；大文本差异、二进制内容在预览中以文件名或截断摘要呈现。

当前恢复从快照重建文件和目录，保存正文及基本权限位；Windows 的 ACL、安全描述符、目录权限、时间戳等其他元数据不保证被完整还原，预览会提示。被移动的原实体保留在 `.agent-hub-transactions/.agent-hub-escrow-*`，可人工核查；不要在确认无用前删除。Windows 对单个指令文件持有拒绝共享写入、允许读取和删除的句柄，已有或新出现的写入句柄会阻止交换；技能目录锁定根目录，并依赖 Windows 对打开后代文件时拒绝目录改名的行为，交换后还会核验移走的目录。文件占用或跨卷配置可能阻止重命名，此时会报告失败并保留冲突。进程异常退出后的恢复使用落盘事务记录，隔离测试覆盖强制终止；**未验证系统断电、磁盘损坏或存储故障后的持久性**。当前安全的无覆盖目录交换实现覆盖 Windows 与支持 `renameat2` 的 Linux；其他平台缺少安全实现时拒绝交换。Linux 的 no-replace 与实体留存不阻止已有文件句柄在重命名后继续写入，不能承诺自动检测全部迟到写入。

## 内部接口

`CapabilityLibrary(root, home)` 的 `root` 是 Hub 数据目录，`home` 是客户端用户目录。`discover()` 返回只读候选；`import_item()` 显式登记；`list_items()` 提供主来源哈希及目标状态；`preview()` 返回短期有效的计划和差异，`discard_preview()` 释放不再使用的预览，`apply()` 复核后发布；`history()` 和 `restore()` 查看或恢复事务；`update_item()` 更新主来源、目标与模式；`remove_item()` 停止跟踪；`sync_auto(item_ids=None)` 为后台调度提供按项同步入口。应用进程重启后应重新生成预览，历史和发布快照仍保留。

自动与手动同步只对已登记条目生效。测试使用独立临时 home：`python -m unittest discover -s tests -p test_capability_library.py -v`。
